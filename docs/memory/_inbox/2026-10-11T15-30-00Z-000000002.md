Codex and Pi budget enforcement (2026-10-11): `squadai budget-hook` takes `--harness claude|codex|pi` (default claude). Codex hooks go in the project `.codex/hooks.json`, not the global config.toml: Codex reads hooks per config layer in the Claude schema, a project file avoids projects fighting over one global file, and the Claude reconcile helpers apply unchanged. Codex needs project trust plus per-hook trust before hooks run; squadai never writes that trust. Codex rejects permissionDecision ask, so ask installs the warn set, and it has no onFailure. Codex usage comes from `ccusage codex session --json --offline` because the rollout format is undocumented (and rollouts older than 7 days are zstd-compressed); ccusage has no project field, so the Codex daily figure is all Codex sessions active in 24h. No ccusage means allow plus one warning per session (marker in the user cache dir). Pi gets `.pi/extensions/squadai-budget.ts` (embedded asset, ENFORCEMENT templated) mapping tool_call, input and agent_before_settle onto the same exit 2 / systemMessage contract; Pi usage comes from Pi's documented session JSONL, which the old `.json` walker never read.
